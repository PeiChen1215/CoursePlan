## 二、发现并修复的缺陷

### 缺陷 1：思考模式把 token 耗尽，模型返回空内容

首次评测准确率只有 **77.3%**，其中多例 `mode=local`、目标为空。

复现：`max_tokens=200` 时返回

```json
{"choices":[{"message":{"content":"","reasoning_content":"We need answer only JSON…"},
             "finish_reason":"length"}],
 "usage":{"completion_tokens_details":{"reasoning_tokens":200}}}
```

`deepseek-flash` 默认开启思考，200 个 token 全花在 `reasoning_content`，`content` 为空 → 我们判定“模型返回空内容”并降级。

修复：请求体显式传 `"thinking": {"type": "disabled"}`（目标映射是分类任务，不需要思维链）；
并把“思考耗尽”与“真返回空”区分成两条错误信息。

### 缺陷 2：模型输出带 ``` 围栏时解析失败

修复：`_parse_json_object()` 先剥 ```` ```json ```` 围栏，再取第一个 `{…}` 子串，
兼顾“前面一句客套话、后面一句解释”的情况。

### 缺陷 3：完成事实的判定范围与数据库约束不一致

`learning_event` 有 `UNIQUE INDEX ux_done_once ON learning_event(task_id) WHERE event_type='done'`，
即“同一任务一辈子只能完成一次”；但看板与 `_has_done()` 都按 `version_id` 过滤。

后果：计划调整后生成新版本，同一任务在新版本里显示“未完成”，用户点打卡 →
撞唯一约束 → 返回 `E1003 UNIQUE constraint failed: learning_event.task_id`（把 SQL 文本抛给了用户）。

修复：完成事实改为**按 task_id 全局判定**（与 D02 AT-25「冻结完成事实」一致）；
并对唯一约束冲突翻译成业务错误「该任务已经打过卡，不能重复完成」。

### 缺陷 4：缺 `Idempotency-Key` 时直接 400

D06 写的是“未带 `Idempotency-Key` 时生成新键”，代码却抛 `E1001 缺少幂等键`。
已改为服务端生成 `uuid4`（与 `/confirm` 行为一致），并补测试。

## 五、局限与后续

1. **标注样本只有 22 条**，且由我编写，存在主观性；正式验收建议由课程组再补 30 条真实提问。
2. **单轮映射**：模型只判断“想学哪个知识点”，不做时间意图解析（日期/时长仍由规则层负责）。
3. **拒答率**未作为指标跟踪；当前 1/15。若提高到 10% 以上，应改成“拒答时强制给候选”的产品策略。
4. 未测并发（两个窗口同时打卡）与限流（429）在真实 API 下的表现，目前只有单测模拟。
