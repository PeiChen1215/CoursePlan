## 2 软件综述

### 2.1 软件的结构

```
浏览器（学生 / 管理员）
   │  HTTP，经 Vite 代理或 Nginx 转发
   ▼
前端 SPA（React 18 + Vite 5）        8 个页面
   │  /api/*  JSON
   ▼
后端 FastAPI（Python 3.12）          12 个模块，32 条路径
   │  sqlite3（WAL）
   ▼
SQLite 数据库（16 表 / 14 索引 / 13 触发器）
   │
   └─ 外部：DeepSeek API（可选，10 s 超时）
```

分层职责：`app/api`（路由与校验入参）→ `app/services`（业务规则）→ `app/db`（事务与存储）；`app/core` 提供配置、错误码、日志、口令与令牌。

### 2.2 程序表

后端 12 个模块与入口如下（标识符沿用 D04/D06 的 M 编号）：

| 模块 | 名称 | 主要入口 | 对应路由 |
|---|---|---|---|
| M-01 | 认证与权限 | `services/auth.py` | `/api/auth/login`、`/api/auth/me` |
| M-02 | 课程内容管理 | `services/content.py`、`services/resource.py` | `/api/courses*`、`/api/concepts*`、`/api/resources*` |
| M-03 | 约束与容量 | `services/constraint.py`、`services/capacity.py` | `/api/plans/{id}/constraint`、`/api/plans/{id}/capacity/preview` |
| M-04 | 追问与抽取 | `services/agent.py`、`services/provider.py` | `/api/agent/extract` |
| M-05 | 分解与排程 | `services/planner.py`、`services/graph.py` | `/api/plans/{id}/drafts`、`PATCH …/drafts/{rev}/tasks` |
| M-06 | 计划校验 | `services/validation.py` | `/api/plans/{id}/drafts/{rev}`、`/api/plans/{id}/explain` |
| M-07 | 确认与版本 | `services/version.py` | `…/drafts/{rev}/confirm`、`/api/plans/{id}/versions*` |
| M-08 | 进度与事件 | `services/progress.py`、`services/timeline.py` | `/api/plans/{id}/events`、`/api/plans/{id}/progress` |
| M-09 | 看板与前端组件 | `services/board.py`、`frontend/src` | `/api/plans/{id}/board` |
| M-10 | 接口与序列化 | `api/deps.py`、`core/errors.py` | 全局信封与错误映射 |
| M-11 | 存储访问 | `db/uow.py` | 事务、重试、迁移 |
| M-12 | 配置与日志 | `core/config.py`、`core/logging.py`、`services/backup.py` | `/api/health`、`/api/meta`、`/api/admin/*` |

前端页面与路由：

| 页面 | 路径 | 主要作用 |
|---|---|---|
| 登录 | `/login` | 账号口令登录；锁定倒计时 |
| 学习看板 | `/board` | 今天 / 本周 / 全部；打卡、查看资料 |
| 学习偏好 | `/constraint` | 一句话解析、目标与期限、可用时间、已掌握 |
| 计划草案 | `/draft` | 生成草案、改时长重排、确认生效 |
| 计划调整 | `/adjust` | 选原因、改截止、差异预览、确认新版本 |
| 学习记录 | `/timeline` | 事件倒序，按类型筛选 |
| 版本历史 | `/versions` | 版本表与两版差异 |
| 课程内容 | `/admin` | 仅管理员：知识点、先修、资料 |

接口清单（32 条路径）见附录 A。

### 2.3 文卷表

数据文卷即 SQLite 表，共 16 张、14 个索引、13 个触发器（触发器强制"只追加"表不可改不可删）。

| 表 | 内容 | 增长方式 | 备份要求 |
|---|---|---|---|
| `schema_meta` | schema 版本号 | 迁移时更新 | 随库 |
| `app_user` | 账号、口令哈希、锁定状态 | 建号时 | 随库，**必须恢复** |
| `course` | 课程信息（当前仅 1 门） | 学期初 | 随库 |
| `concept` | 知识点、章节、难度、参考时长 | 学期初 | 随库 |
| `prerequisite` | 先修边（无环） | 学期初 | 随库 |
| `resource` | 学习资料 | 学期中 | 随库 |
| `concept_resource` | 知识点—资料关联 | 学期中 | 随库 |
| `study_plan` | 学生计划，指向当前版本 | 建计划时 | 随库，**必须恢复** |
| `plan_constraint` | 约束与可用时间 | 每次保存 | 随库 |
| `plan_task` | 任务（稳定 ID） | 生成草案时 | 随库 |
| `plan_draft` | 草案 payload（JSON） | 每次生成 | 可丢（可重生） |
| `plan_version` | 版本快照（含原因、说明） | 每次确认 | 随库，**必须恢复** |
| `version_task` | 版本内任务（含覆盖时长） | 每次确认 | 随库，**必须恢复** |
| `task_slice` | 时间片（start/end 为 epoch 秒） | 每次确认 | 随库 |
| `plan_validation` | 校验结果（只追加） | 每次校验 | 可丢 |
| `learning_event` | 打卡/更正/备注（只追加） | 每次操作 | 随库，**必须恢复** |

**存储要求**：数据库文件 + `-wal`、`-shm` 必须在同一目录；备份必须用 SQLite 备份 API（`POST /api/admin/backup`），**不要直接复制主库文件**——WAL 模式下直接复制可能拿到不一致快照。

## 3 安装与初始化

### 3.1 环境准备

| 项 | 要求 | 检查命令 |
|---|---|---|
| Python | 3.12 | `python --version` |
| Node.js | 20 LTS 及以上 | `node -v` |
| pnpm | 9 及以上 | `pnpm -v` |
| 磁盘 | ≥ 10 GB（库约 250 MB，备份按 7 份计） | `df -h` / `Get-PSDrive` |

### 3.2 安装步骤

```powershell
# 1) 取代码
git clone <仓库地址> CoursePlan
cd CoursePlan

# 2) 后端依赖
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # Linux: source .venv/bin/activate
pip install -r requirements.txt

# 3) 前端依赖
cd ..\frontend
pnpm install
```

### 3.3 配置

复制模板并按需修改（**`.env` 不入库**）：

```powershell
cd ..\backend
Copy-Item .env.example .env
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `DB_PATH` | `data/studypath.db` | 相对路径以项目根为基准 |
| `LOG_LEVEL` | `INFO` | DEBUG / INFO / WARNING / ERROR |
| `PROVIDER_MODE` | `mock` | `mock` 离线可复现；`real` 调真实模型；`auto` 启动探测 |
| `PROVIDER_MODEL` | `deepseek-flash` | 该账号可用的模型名 |
| `PROVIDER_THINKING` | `disabled` | 抽取是分类任务，关思考否则 token 会被推理耗尽 |
| `PROVIDER_KEY` | 空 | 仅填在本地 `.env` 或环境变量 |
| `BACKUP_KEEP` | `7` | 备份保留份数 |

### 3.4 初始化数据库

```powershell
# 演示/验收：整库重建并灌入演示数据
python scripts\seed.py --db ..\data\dev_ui.db

# 生成计划但不要演示计划（空白学生视角）
python scripts\seed.py --db ..\data\dev_ui.db --no-plan

# 只建表不灌数据
python -m uvicorn app.main:app --port 8000   # 启动时自动建表
```

`seed.py` 拒绝在被占用的库上执行；如提示"数据库被占用"，先停后端。

### 3.5 启动

```powershell
# 终端 1：后端
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 终端 2：前端（开发/内网演示）
cd frontend
pnpm dev --host 0.0.0.0 --port 5173

# 生产：先构建再托管静态文件
pnpm build      # 产物在 frontend/dist，用 Nginx 指向该目录，/api 反代到 8000
```

### 3.6 安装完成的验证

| 检查 | 期望结果 |
|---|---|
| `GET http://<host>:8000/api/health` | `{"service":"ok","database":"ok","provider":"real|mock"}` |
| 打开 `http://<host>:5173` | 出现登录页 |
| 用 `alice / Passw0rd!` 登录 | 进入看板并看到 22 个任务（演示库） |
| `GET /api/meta` | 返回引擎版本与配置摘要（不含密钥） |

演示账号：`alice / Passw0rd!`（学生，已确认计划）、`bob / Bob12345!`（学生，空计划）、`carol / Carol123!`（学生）、`admin / Admin123!`（管理员）。

## 4 运行说明

> 本模板把"一次运行"定义为"提供一次启动控制信息后，系统执行的全部过程"。在 Web 系统里，一次运行即"一个角色从登录到退出的完整场景"。

### 4.1 运行表

| 运行 | 标识符 | 目的 | 执行入口 |
|---|---|---|---|
| 1 | RUN-PLAN | 学生首次制定学习计划 | `/constraint` → `/draft` |
| 2 | RUN-DAILY | 学生日常打卡与查看进度 | `/board` |
| 3 | RUN-ADJUST | 进度落后或目标变化后重排 | `/adjust` |
| 4 | RUN-ADMIN | 管理员维护课程内容与备份 | `/admin`、`/api/admin/*` |

### 4.2 运行步骤

四个运行之间的流转：

```
RUN-ADMIN（学期初维护课程）
    │  知识点 + 先修 + 资料就绪
    ▼
RUN-PLAN（学生建约束 → 生成草案 → 确认 v1）
    │  v1 生效
    ▼
RUN-DAILY（每天打卡，进度累积）
    │  出现逾期 / 目标变化
    ▼
RUN-ADJUST（选原因 → 重排 → 看差异 → 确认 v2）──┐
    │                                            │
    └────────── 回到 RUN-DAILY ◀─────────────────┘
```

### 4.3 运行 1（RUN-PLAN）说明

#### 4.3.1 运行控制

| 项 | 规则 |
|---|---|
| 前置条件 | 课程存在且状态为 `enabled`；学生账号可用 |
| 顺序 | 必须"先保存约束，再生成草案，最后确认"；跳步会被拒绝 |
| 分支 | 模型不可用 → 仍可手填；容量不足 → 生成草案但"未排入"非空，确认被禁 |
| 结束条件 | 返回 `version_no = 1` 且 `board.current_version = 1` |

#### 4.3.2 操作信息

| 项 | 内容 |
|---|---|
| 运行目的 | 把"想学什么、有多少时间"变成一份可执行的计划 |
| 操作要求 | 至少选 1 个可用时段；截止日期不早于今天 |
| 启动方法 | 学生登录后点击左侧「学习偏好」 |
| 预计耗时 | 首次 5–8 分钟（含思考时间） |
| 操作命令 | 无（界面操作）；等价接口见 4.3.3 |
| 关联事项 | 需要课程已由 RUN-ADMIN 完成初始化 |

#### 4.3.3 输入输出文卷

| 方向 | 表 | 写入时机 |
|---|---|---|
| 写 | `study_plan` | 首次创建计划 |
| 写 | `plan_constraint` | 保存约束 |
| 写 | `plan_draft` | 每次生成草案（自增 `revision`） |
| 写 | `plan_task` | 首次生成草案时建立稳定任务 ID |
| 写 | `plan_version`、`version_task`、`task_slice` | 确认时 |
| 写 | `plan_validation` | 每次校验（只追加） |
| 读 | `course`、`concept`、`prerequisite`、`resource` | 计算闭包与时长 |

等价接口调用顺序：

```
PUT  /api/plans/{id}/constraint
POST /api/plans/{id}/capacity/preview
POST /api/plans/{id}/drafts
GET  /api/plans/{id}/drafts/{revision}
POST /api/plans/{id}/drafts/{revision}/confirm   （需 Idempotency-Key）
```

#### 4.3.4 输出文段

| 标识符 | 输出 | 媒体 |
|---|---|---|
| MSG-CAP | 容量摘要 `C / B / C′ / 目标路径 / 可用时段` | 屏幕 |
| MSG-DRAFT | 草案任务表 + 校验报告 | 屏幕 |
| MSG-CONFIRM | `已生成 v1` 提示 | 屏幕（toast） |
| ERR-* | 失败时的错误码与说明 | 屏幕 |

#### 4.3.5 输出文段的复制

| 项 | 说明 |
|---|---|
| 可复制内容 | 校验报告、任务清单、版本差异（浏览器选中复制） |
| 打印 | 浏览器打印；周课表支持黑白打印（状态另有文字标注） |
| 分发 | 无需分发；如需留档，用打印为 PDF |
| 份数 | 不限 |

#### 4.3.6 恢复过程

| 失败点 | 现象 | 恢复 |
|---|---|---|
| 保存约束失败 | 提示 `E1001` 并指出字段 | 按提示改字段后重新保存，已填内容不清空 |
| 生成草案失败 | 提示 `E1003`（无可用时段等） | 回约束页增加可用时间后重试 |
| 确认失败 | `E2004 版本冲突` | 重新生成草案再确认（旧草案已过期） |
| 中途关闭浏览器 | 已保存的约束仍在 | 重新登录后从「计划草案」继续 |
| 服务重启 | 前端提示请求失败 | 刷新页面；数据库为 WAL，已提交数据不丢 |

### 4.4 运行 2（RUN-DAILY）说明

#### 4.4.1 运行控制

| 项 | 规则 |
|---|---|
| 前置条件 | 计划已有确认版本（`current_version ≥ 1`） |
| 顺序 | 打开看板 → 点时间块或「完成打卡」 → 填实际用时 → 提交 |
| 分支 | 重复打卡被拒（`E1003`）；改时用「更正」，会保留指向关系 |
| 结束条件 | 看板进度刷新，事件表新增一行 |

#### 4.4.2 操作信息

| 项 | 内容 |
|---|---|
| 运行目的 | 记录真实投入，驱动进度与逾期判断 |
| 操作要求 | 实际用时填分钟数；备注可选 |
| 启动方法 | 登录后默认进入看板 |
| 预计耗时 | 每次 10–30 秒 |
| 操作命令 | 无；等价接口 `POST /api/plans/{id}/events`（带 `Idempotency-Key`） |
| 关联事项 | 逾期超过 48 小时会触发"建议调整"提示 |

#### 4.4.3 输入输出文卷

| 方向 | 表 | 说明 |
|---|---|---|
| 写 | `learning_event` | 仅追加；`event_type ∈ {done, correction, note}`；`ux_done_once` 保证同一任务只完成一次 |
| 写 | `study_plan.progress_revision` | 每次事件 +1，用于并发检测 |
| 读 | `version_task`、`task_slice`、`plan_version` | 渲染课表 |

#### 4.4.4 输出文段

| 标识符 | 输出 |
|---|---|
| MSG-DONE | `已打卡：<知识点>` |
| MSG-CORR | `已更正用时` |
| MSG-REPLAY | 同键重放返回 `replayed: true`，不重复计数 |
| MSG-OVERDUE | `有 N 个任务已逾期 M 小时，建议调整计划` |

#### 4.4.5 输出文段的复制

不涉及打印复制；进度数据可通过「学习记录」页查看，或由管理员通过备份留档。

#### 4.4.6 恢复过程

| 失败点 | 恢复 |
|---|---|
| 打卡网络中断 | 用同一幂等键重试，不会重复计数 |
| 打错了用时 | 「更正用时」写一条更正事件 |
| 任务已过期仍要完成 | 允许打卡，但会保留"逾期完成"的事实用于统计 |
| 误删记录 | 不支持删除（只追加）；如确需更正，追加更正事件 |

### 4.5 运行 3（RUN-ADJUST）说明

#### 4.5.1 运行控制

| 项 | 规则 |
|---|---|
| 前置条件 | 至少有一个已确认版本 |
| 顺序 | 选原因 →（可选）改截止日期 → 重排预览 → 看差异 → 确认 |
| 分支 | 有 ERROR 时禁止确认；与当前版本无差异时仍可确认（会产生内容一致的新版本） |
| 结束条件 | `version_no` 递增，旧版本转只读 |

#### 4.5.2 操作信息

| 项 | 内容 |
|---|---|
| 运行目的 | 让计划跟上现实（落后、目标变、时间变、估时变） |
| 操作要求 | 原因必选；说明可选但建议写 |
| 启动方法 | 左侧「计划调整」 |
| 预计耗时 | 1–3 分钟 |
| 操作命令 | 无；等价接口 `POST /api/plans/{id}/drafts` → `confirm`（带 `change_reason`） |
| 关联事项 | 已完成的事实不会被改写 |

#### 4.5.3 输入输出文卷

| 方向 | 表 | 说明 |
|---|---|---|
| 写 | `plan_draft` | 新一期草案 |
| 写 | `plan_version` | `change_reason` ∈ {initial, delay, goal_change, availability_change, duration_change, manual} |
| 写 | `version_task`、`task_slice` | 新版本的任务与片 |
| 读 | `learning_event` | 已完成任务不计入未完成 |

#### 4.5.4 输出文段

| 标识符 | 输出 |
|---|---|
| MSG-DIFF | `新增 / 移除 / 移动 / 时长变化` 四类计数 |
| MSG-METRIC | 新容量 `T / C′ / 缺口 D / 利用率 U` |
| MSG-NEWVER | `已生成 vN（进度延后）` |

#### 4.5.5 输出文段的复制

差异清单可复制粘贴到周报；也可在「版本历史」选用任意两版对比后打印。

#### 4.5.6 恢复过程

| 失败点 | 恢复 |
|---|---|
| 预览后发现不合理 | 直接「取消」，不产生新版本 |
| 确认后才发现算错 | 再走一次 RUN-ADJUST；旧版本保留，可对比回溯 |
| 版本冲突（他处已确认） | 重新生成草案 |

### 4.6 运行 4（RUN-ADMIN）说明

#### 4.6.1 运行控制

| 项 | 规则 |
|---|---|
| 前置条件 | 账号角色为 `admin` |
| 顺序 | 维护课程信息 → 知识点 → 先修边（整批提交）→ 资料与关联 → 备份 |
| 分支 | 先修成环 → 整批拒绝并返回环路；知识点被版本引用 → 只能停用 |
| 结束条件 | 内容修订号 `content_revision` 递增；备份文件落盘并通过完整性检查 |

#### 4.6.2 操作信息

| 项 | 内容 |
|---|---|
| 运行目的 | 保证课程内容正确、可追溯，并在变更前留底 |
| 操作要求 | 改课程内容前先做一次备份 |
| 启动方法 | 左侧「课程内容」（仅管理员可见） |
| 预计耗时 | 首次录入 30–60 分钟；日常维护 2–5 分钟 |
| 操作命令 | 无；备份可命令行触发（见 4.6.3） |
| 关联事项 | 停用课程后学生无法新建计划，历史计划仍可打开 |

#### 4.6.3 输入输出文卷

| 方向 | 表 | 说明 |
|---|---|---|
| 写 | `course` | 名称、学时、状态（PATCH `/api/courses/{id}`） |
| 写 | `concept` | 新增/修改知识点；被引用时只能停用 |
| 写 | `prerequisite` | 批量提交，成环拒绝 |
| 写 | `resource`、`concept_resource` | 资料与关联 |
| 写 | `backups/*.db` | 备份文件（`POST /api/admin/backup`） |

命令行备份（等价于接口）：

```powershell
curl -X POST http://127.0.0.1:8000/api/admin/backup -H "Authorization: Bearer <管理员令牌>"
curl http://127.0.0.1:8000/api/admin/backups -H "Authorization: Bearer <管理员令牌>"
```

#### 4.6.4 输出文段

| 标识符 | 输出 |
|---|---|
| MSG-CYCLE | `HTTP 422 / E2001 / 环路 [13,14,13]` |
| MSG-IMPACT | 停用知识点的影响范围（被哪些版本引用） |
| MSG-BACKUP | `studypath-<时间戳>.db / 大小 / integrity=ok / 外键问题 0` |

#### 4.6.5 输出文段的复制

备份文件需要复制到异地时，**复制备份文件而不是主库**；恢复见 5.3。

#### 4.6.6 恢复过程

| 失败点 | 恢复 |
|---|---|
| 误停用知识点 | 重新启用（若未被删除）；已停用的历史任务仍可打开 |
| 先修关系改错 | 重新提交正确的边集合（整批覆盖） |
| 误改课程名称 | PATCH 改回；历史版本中的课程名不受影响（快照） |

## 5 非常规过程

### 5.1 模型不可用

| 现象 | 判定 | 处置 |
|---|---|---|
| 解析耗时接近 10 s 后返回结果 | 已超时降级 | 正常现象；界面标注"规则解析"。检查网络与密钥后重试 |
| 界面提示"模型不可用，已降级为规则解析" | 401/403/网络错误 | 检查 `.env` 中 `PROVIDER_KEY`；用 `GET /models` 验证密钥 |
| 所有请求都在 0.3 s 内返回且都降级 | 密钥错误或未加载 | 重启后端使 `.env` 生效 |

### 5.2 数据库被占用

`seed.py` 报"数据库被占用（后端还在运行？）"时：先停后端，再执行种子脚本，最后重启。SQLite 允许多进程读，但整库重建需要独占。

### 5.3 备份与恢复

```powershell
# 备份（管理员）
POST /api/admin/backup
# 列出
GET  /api/admin/backups
# 恢复（会把当前库另存为 *.before-restore-<时间戳> 再覆盖）
POST /api/admin/restore  {"name": "studypath-20261109-153243.db"}
```

恢复后校验：`integrity_check = ok`、外键违例 = 0，并核对 `app_user`、`plan_version`、`learning_event` 三表行数。

### 5.4 令牌过期与锁定

| 现象 | 处理 |
|---|---|
| 页面突然跳回登录页 | 令牌 24 小时过期，重新登录 |
| 提示"请等待 N 秒" | 连续输错 5 次锁定 5 分钟；等待或由管理员在库中清零 `failed_attempts` |
| 管理员需解锁账号 | `UPDATE app_user SET failed_attempts=0, locked_until=NULL WHERE username=?` |

### 5.5 进程异常退出

| 检查项 | 命令/方法 |
|---|---|
| 是否有残留锁 | 查看 `data/*.db-wal`、`*.db-shm` 是否异常增大 |
| 数据是否完整 | `PRAGMA integrity_check;` |
| 恢复到最近备份 | 见 5.3 |

### 5.6 磁盘空间不足

先清理旧备份（保留最近 3 份即可），再清理日志；`BACKUP_KEEP` 可下调。不要删除 `-wal` 文件（会让已提交但未检查点的数据丢失）。

## 6 远程操作

| 项 | 说明 |
|---|---|
| 访问方式 | 学生浏览器访问 `http://<服务器地址>:5173`；后端 `:8000` 仅需对前端开放 |
| 反向代理 | 生产建议 Nginx：`/` → `frontend/dist`，`/api` → `http://127.0.0.1:8000` |
| 跨域 | 开发模式由 Vite 代理 `/api`，无需 CORS；若前后端分域部署，后端需允许来源 |
| 远程终端 | 本系统不提供 SSH/远程 shell，运维通过服务器本地或既有远程桌面操作 |
| 安全建议 | 仅在内网开放；如对外发布，务必启用 HTTPS 并更换默认账号口令 |
| 移动访问 | 支持手机浏览器（390 px 起）；周课表可左右滑动，底部为五项导航 |
