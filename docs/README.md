## 三、编写约定

1. **单一事实源**：需求、设计、代码三者冲突时，以 `docs/02_需求/` 与 `docs/03_设计/` 的最新版本为准，代码必须回改对齐。
2. **版本与文件名**：`D02_软件需求说明书_v0.3_20261030.md`；定稿版本另存为 `..._终稿.md`，不覆盖历史版本。
3. **变更留痕**：需求或设计的任何变更，在文末「变更记录」表追加一行（日期 / 版本 / 变更内容 / 原因 / 提出人）。
4. **不写没做的事**：文档中描述的功能必须能在本仓库代码中演示；未实现内容放入「后续工作」，不得写入功能章节。
5. **图表要求**：架构图、ER 图、用例图、时序图、状态图用 Mermaid 写在正文里，便于评审与版本对比。
6. **术语一致**：统一使用《软件需求说明书》1.3 节「定义」中的术语表。
