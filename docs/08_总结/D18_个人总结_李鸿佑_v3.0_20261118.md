## 一、总体情况说明

我在本组负责学生端前端与交互。项目最终交付 8 个学生端页面（看板、计划草案、计划调整、学习记录、课程测评、版本历史、学习偏好、课程内容），加上管理端的框架与通用组件，前端构建体积 319 KB（gzip 98 KB），63 项前端测试通过。

我的工作贯穿三个阶段：设计阶段做页面结构与交互原型；编码阶段实现页面与组件、对接后端接口；测试阶段修可访问性与交互细节、产出演示脚本与截图。收尾时配合组长把用户手册（D11）的 26 张界面截图全部重拍，确保文档里的界面与代码一致。

## 二、个人成果展示

**1. 页面与交互**

- **看板**：今天/本周切换、逾期提示、任务卡片点击展开资料、右栏完成率与剩余容量；任务"标记完成"后完成率即时刷新，已完成任务只能"更正"，体现"完成事实不可撤销"。
- **计划草案**：生成草案后展示任务、时间片与校验报告；改某行时长（如 135 分钟）可"按新时长重排"，界面显示 120 + 15 两片，合计不变。
- **计划调整**：选择调整原因（进度延后/目标变化/时间变化/其他）→ 预览差异（新增、删除、改期、改时长）→ 确认生效生成新版本。
- **学习偏好**：一句话输入 → 调用抽取 → 显示"模型解析"标签，自动填目标与截止，可手改；下方"预览容量"显示 C / B / C′。
- **课程测评**：试卷列表、作答（单选 + 简答）、提交后报告（题干、你的选择、正确答案、要点、判分理由、引用原话）；得分 ≥80% 时出现"采纳建议：标记为已掌握"。
- **版本历史**：版本列表、只读快照、两版差异；管理端"班级学情"卡片由我实现了统计条、逐题得分率表与分数分布。

**2. 通用组件与样式**

封装了卡片、表格、统计条、Chip、Toast、ErrorBox、Onboarding 等组件；用一份 `product.css` 统一间距、圆角、描边与字号层级，页面之间不再各写一套。表格统一"题注在上、表头不换行、数字右对齐"，与文档里的表格规范保持一致。

**3. 可访问性与体验修复（12 项）**

对比度不足的次级文字、焦点不可见的按钮、Esc 不能关闭的弹层、只能鼠标操作的菜单、表单标签缺失、错误提示不读屏等问题，逐项对照修复；修复后回归 15/15 通过。

**4. 演示与文档配图**

编写并维护 Playwright 脚本：学生端全流程、管理端出题与学情、双标签页身份切换等场景，一键产出截图；D11 用户手册的 26 张图由脚本生成，改版后重跑即可，不用手工截。

**5. 发现并推动修复的问题**

演示前发现"管理员点 AI 出题提示无权限"：同一浏览器两个标签页分别登录管理员与学生时，`localStorage` 只有一份令牌，管理员页签带的是学生令牌。我把复现步骤整理给组长，最终通过监听 `storage` 事件同步身份、403 时提示重新登录解决。

## 三、实训总结

**个人感受**：前端最容易"看起来做完了"。页面能点开、数据能显示，不等于做完了——状态同步（切了计划，看板要跟着变）、边界态（没计划、没试卷、模型超时）、可访问性，这些才是用户真正会遇到的部分。这次把"加载中/空/错误"三态当成硬要求，页面返工少了很多。

**个人评价**：交互细节和视觉一致性是我的强项，页面还原度、空态与错误态处理得比较完整；不足是前端测试偏薄——63 项里页面级只有 3 个测试文件，很多交互靠手工回归，改版时容易漏。下一步会补页面级测试（至少覆盖作答提交、报告渲染、计划切换三条链路）。

**意见与建议**：建议课程在前端部分加一次"状态管理与接口契约"的短讲，我们是踩了"切课程后其他页面仍显示旧计划"的坑才引入统一的当前计划状态；另外希望验收时除了看功能，也看一下空态与错误态，这是最容易看出工程质量的地方。
