## 4 设计说明

### 4.1 层次与接口

```
api（路由）──▶ services（业务）──▶ db（UoW）──▶ SQLite
     │                │
     └── core（配置 / 错误码 / 日志 / 口令与令牌 / provider）
```

表 4.1 层次与接口

| 调用方向 | 接口 | 约束 |
|---|---|---|
| api → services | 构造函数注入 `Database` 与 `EngineConfig` | 服务不感知 HTTP；服务抛业务异常，由 api 层映射 |
| services → db | `UnitOfWork`（上下文管理器） | 一次业务操作一个事务；读操作走 `db.query` 不开启写事务 |
| services → provider | `BaseProvider.complete(prompt) -> str` | 只返回文本；异常分 `ProviderTimeout` / `ProviderError` 两类 |
| services 之间 | M-05 调用 M-03（容量）、M-02（图）；M-07 调用 M-06（校验） | 禁止反向依赖；M-09 只读 |

### 4.2 关键算法与处理流程

表 4.2 关键算法与处理流程

| 模块 | 算法/流程 | 依据 |
|---|---|---|
| M-02 | 环路检测：DFS 三色标记；整批插入前先在内存图中试插，成环则整批回滚并返回环路路径 | D06 §4.5 |
| M-03 | 时段展开：周模板 × 日期区间 − 排除日期；容量用分钟整数累加 | D06 §5.5 |
| M-05 | 拆分：学习 `L=⌊7T/10⌋`（用 `Fraction` 避免浮点误差），练习 `T−L`；超 120 分钟按 `MAX_SLICES_PER_TASK` 切片；装箱贪心，装不下进"未排入" | D06 §7.6 |
| M-06 | 规则表驱动：每条规则一个函数，返回问题码；容量与缓冲用同一份 C/C′，避免口径不一致 | D06 §8.5 |
| M-07 | 确认三步：幂等检查 → 校验复算 → 写快照；快照写入后旧版本 `frozen=1` | D06 §9.4 |
| M-08 | 完成判断按 `task_id` 全局（与 `ux_done_once` 一致）；完成率 = 已完成 ÷ 当前版本任务数 | D06 §10.5 |
| M-04 | 目标映射四层：精确 → 包含（取最长匹配）→ 别名 → 模型（限候选内）；模型输出先剥围栏再取首个 JSON 对象 | D06 §6.6 |
| M-12 | 备份用 SQLite 官方 backup API（WAL 下直接复制会不一致）；备份后跑 `integrity_check` 与 `foreign_key_check` | D06 §13.6 |
