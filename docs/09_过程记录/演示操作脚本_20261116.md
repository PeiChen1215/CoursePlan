# 答辩演示脚本（v2）

> 适用：课程验收 / 答辩现场。总时长 12–15 分钟。
> 数据前提：`data/dev_ui.db` 已由 `scripts/seed.py` 重置，且跑过一次 `scripts/prepare_demo.py`
> （已发布 1 份测评，alice / bob 各作答 1 次）。
> 服务：`.\scripts\start_demo.ps1`（后端 8000 + 前端 5173）。若 8000 被占用，见文末"备用启动"。

---

## 0. 开场（1 分钟，不放 PPT 也行）

讲三句话，把问题立住：

1. "学生真正难的不是'记下今天学什么'，而是**这些时间够不够、先学哪个、落后了怎么办**。"
2. "便签能记任务，但算不出容量、排不出先修顺序、更不会因为落后而重排。"
3. "而且一个人一学期不止一门课——**同一个晚上不能被两门课同时排走**。"

如果老师追问依据，直接切到"证据"：两门课同一可用时段，系统排出的时间片**零重叠**（跨课程占位）。

## 1. 管理员：课程与出题（3 分钟）

用 `admin / Admin123!` 登录。

| 步骤 | 操作 | 讲什么 |
|---|---|---|
| 1.1 | 左侧「课程内容」 | 两门课程可同时启用；知识点表里每个知识点都有**要点**——这是出题依据，不是摆设 |
| 1.2 | 点某个知识点的「未填 · 填写」 | 现场把要点补一句、保存，说明"管理员改的东西学生端立刻生效" |
| 1.3 | 左侧「课程测评」→ 选课程 + 知识点 →「AI 出题」 | 真实模型 1–2 秒出 4 题（2 单选 + 2 简答）；草稿里带答案键，学生看不到 |
| 1.4 | 检查题目 → 点「发布」 | 强调**发布制**：AI 出的题必须经过人审，学生看到的才是审核过的 |

**看点**：题目不是通用题，是扣着要点出的（例如"聚合/组合的生命周期区别"）。

## 2. 学生 A：从计划到打卡（4 分钟）

用 `alice / Passw0rd!` 登录（建议换无痕窗口，避免与管理员会话互相覆盖）。

| 步骤 | 操作 | 讲什么 |
|---|---|---|
| 2.1 | 看板「今天」/「本周」 | 逾期提示"有 N 个任务已逾期 M 小时，建议调整"；点任务能看到资料 |
| 2.2 | 点一个未完成任务 →「标记完成」 | 右栏完成率立刻变化；已完成的任务只能"更正"，**完成事实不可撤销** |
| 2.3 | 左侧「学习偏好」→ 输入一句话 →「解析」 | 右上角出现**「模型解析」**标签；自动填目标与截止；不满意可手改 |
| 2.4 | 「预览容量」 | C / B / C′ 三个数满足 `C′ = C − B`，B ≈ 10%C；这是"排不排得下"的依据 |
| 2.5 | 「计划草案」→「生成草案」 | 任务按 7:3 拆学习/练习；超过 2 小时的任务被切片；校验报告为"通过" |
| 2.6 | 改某行时长为 135 →「按新时长重排」 | 变成 120 + 15 两片，**合计仍 135**（这是测试里的硬断言） |
| 2.7 | 「确认生效」→「版本历史」 | 生成 v2；旧版本只读；`原因` 列有中文（进度延后/目标变了…） |
| 2.8 | 看板「问一句」→ 点预设问题 | 模型回答里每个数字（1180 / 1026 / 154）都能在右栏找到出处；下方标注"模型作答 · 依据：…" |

**看点**：2.6 的"合计不变"、2.8 的"数字有出处"——这两处最能说明"程序算数，模型只说话"。

## 3. 学生 B：测评与报告（2.5 分钟）

用 `bob / Bob12345!` 登录。

| 步骤 | 操作 | 讲什么 |
|---|---|---|
| 3.1 | 左侧「课程测评」→ 选那份已发布试卷 →「开始作答」 | 学生只看到题干与选项，**看不到答案键** |
| 3.2 | 选择题随便选、简答写一两句 →「提交并看报告」 | 立即出分 |
| 3.3 | 看报告 | 逐题显示：题干 / 你的选择 / **正确答案** / 要点 / 判分理由 / 引用原话（仅简答） |
| 3.4 | 指出低分题的"判分理由" | 例如"未点明组合与聚合在部分能否独立存在上的区别"——老师能直接看出为什么扣分 |
| 3.5 | 如果得分 ≥ 80% | 会出现「采纳建议：标记为已掌握」，点后重排不再排该知识点 |

**看点**：判分不是黑盒——选择题程序判、简答题模型判但给理由，分数越界或模型不可用会标"待人工复核"。

## 4. 回到管理员：班级学情（2 分钟）

用 `admin` 回到「课程测评」页，选刚发布/作答的试卷看「班级学情」。

| 指标 | 讲什么 |
|---|---|
| 作答人数 / 平均分 / 及格率 / 最高最低 | 一眼看班级整体 |
| 逐题得分率 | **哪道题低于 60%**，说明这个知识点全班没掌握，讲评先讲它 |
| 分数分布 | <50% / 50–70% / 70–85% / ≥85% 四档人数 |
| 最近提交 | 谁交了、多少分 |

**看点**：学情全部是 SQL 聚合，**不调用模型**，打开即出；讲评时"用数据决定先讲哪道题"。

## 6. 老师可能问的四个问题

| 问题 | 回答要点 |
|---|---|
| 这和日历/便签有什么区别？ | 便签不会算容量、不会按先修排、不会因为落后生成新版本；我们的计划有 C/B/C′、校验、版本快照与事件台账 |
| 模型算错了怎么办？ | 选择题程序判分；简答有判分理由与引用，可人工复核；分数越界或模型不可用会转"待人工复核" |
| 学生会不会乱点"已掌握"？ | "已掌握"可由测评 ≥80% 建议，也可手勾；两者都会在下一次重排时体现，且历史版本可追溯 |
| 数据存在哪、密钥安全吗？ | SQLite 单文件 + 备份；模型密钥只在服务器 `.env`，不进仓库（`git grep` 可验证历史无泄露） |

## 7. 备用与回滚

```powershell
# 8000 被占用时换端口
.\scripts\start_demo.ps1 -Mock        # 无网络：解析降级为"本地模拟"，测评出题不可用（用已有试卷作答）
.\scripts\stop_demo.ps1               # 停止

# 数据重置
cd backend
python scripts\seed.py --db ..\data\dev_ui.db     # 干净数据（无作答记录）
python ..\scripts\prepare_demo.py                 # 重新出题 + 两次作答（需要真实模型）

# 现场发现数据被改乱
.\scripts\start_demo.ps1 -Reset
```

**三条现场纪律**

1. 一个浏览器只登一个账号；切换账号用无痕窗口（否则会提示"登录身份已变化"）。
2. 演示前 5 分钟先按本文跑一遍 2.1 / 2.8 / 3.3 / 4，确认模型可用。
3. 任何一屏卡住，直接讲"这里依赖模型，我们降级后仍可用"，然后切到已发布试卷继续。
