# 演示操作脚本

> 适用：2026-11-16 起，答辩/验收现场演示。
> 环境：本机 Windows，后端 8000、前端 5173。
> 演示数据：`data/dev_ui.db`（12 知识点 / 12 先修 / 6 资料 / 1 份已确认计划 22 任务）。

---

## 一、启动与停止

```powershell
# 启动（已在运行则跳过，可重复执行）
.\scripts\start_demo.ps1

# 重置演示数据后启动（会把打卡记录清掉，恢复到初始 22 个任务）
.\scripts\start_demo.ps1 -Reset

# 没有网络或不想让模型调用出现在演示里，用离线模式
.\scripts\start_demo.ps1 -Mock

# 停止
.\scripts\stop_demo.ps1
```

启动后浏览器打开 <http://127.0.0.1:5173>。

| 账号 | 口令 | 用途 |
|---|---|---|
| `alice` | `Passw0rd!` | 学生，已有 v1 计划（22 任务 / 29 片），适合演示"看板与打卡" |
| `bob` | `Bob12345!` | 学生，空计划，适合演示"从零建计划" |
| `admin` | `Admin123!` | 管理员，课程内容与备份 |
| `carol` | `Carol123!` | 学生，备用账号 |

## 三、主推演示线（约 8 分钟）

### 1. 从一句话到计划（用 `bob`，空计划）

1. 登录 `bob`，首次会弹三步引导 → 点「稍后设置」。
2. 左侧「学习偏好」→ 打开浏览器网络面板（可选，用于证明真的调了模型）。
3. 在「一句话描述」输入：

   > 我想把那块讲数据流的东西学会，两周内

4. 点「解析」。**观察点**：
   - 卡片右上角出现 **「模型解析」** 标签（若显示"规则解析"，说明模型不可用已降级）；
   - 目标自动选到「结构化设计」，截止日期自动填为两周后；
   - 下方出现追问，并以"你 / 系统"两行记录，可继续补一句话。
5. 在「每周可用时间」点亮：周一 19–21、周三 19–21、周六 9–11。
6. 点「预览容量」。**观察点**：C / B / C′ 三个数字满足 `C′ = C − B`，且 `B ≈ 10%C`。
7. 点「保存约束」→ 去「计划草案」→「生成草案」。
8. 草案页展示任务清单与校验结果。**观察点**：
   - 每个知识点拆成"学习 + 练习"两行，比例约 7:3；
   - 超过 2 小时的任务被切成多片（片数列 > 1）；
   - 校验报告为"通过"。
9. 把某行时长改成 `135`，点「按新时长重排」。**观察点**：该任务变成 2 片（120 + 15），合计仍 135。
10. 点「确认生效」→ 生成 v1，看板出现彩色时间块。

### 2. 日常打卡与进度（用 `alice`）

1. 登录 `alice`，看板默认「今天」；点「本周」看完整课表。
2. **观察点**：块的颜色区分学习/练习；逾期块带红色斜纹与「逾期」字样；已完成的块变为绿色并加勾。
3. 点任意未完成块 → 弹层显示该知识点的资料（如"需求工程速览 · 文档 · 25 分钟"）。
4. 填实际用时（如 88 分钟）→「标记完成」。**观察点**：右栏进度环与 `x / 22 项已完成` 同步变化，底部出现"已打卡"提示。
5. 再点一个已完成块 → 只有「更正用时」，重复打卡会被拒绝（说明"完成事实不可撤销，只能更正"）。
6. 左侧「学习记录」。**观察点**：打卡 / 更正 / 备注按时间倒序，更正那条带"更正了 #编号"。

### 3. 调整与版本（用 `alice`）

1. 看板顶部若出现橙色提示「有 N 个任务已逾期 …，建议调整计划」，正好作为切入点；否则直接进「计划调整」。
2. 选「进度落后了」→ 把截止日期改到更晚（如 `2026-12-20`）→「重排并预览」。
3. **观察点**：
   - 「与当前版本对比」给出新增 / 移除 / 移动 / 时长变化四类计数；
   - 新的容量 T / C′ / 缺口 D / 利用率 U；
   - 校验报告通过后才能点「确认这次调整」。
4. 点「确认这次调整」→ 生成 v2。左侧「版本历史」。**观察点**：v1 标"当前"以外为只读，点「与当前对比」可看差异；`原因` 列显示中文（首次规划 / 进度延后 …）。

### 4. 管理员线（用 `admin`，约 2 分钟）

1. 登录 `admin` → 左侧「课程内容」。
2. 知识点表、先修关系、课程资料三块。**观察点**：先修关系是"先修 → 后继"的对列表；资料带类型与阅读分钟。
3. 在「先修关系」里制造环路：选 `A 先于 B`、再选 `B 先于 A` → 提交。**观察点**：整批拒绝，提示 `HTTP 422 / E2001` 并给出环路 `13→14→13`。
4. 演示停用课程：点「停用课程」→ 行内出现二次确认（不是浏览器弹窗）→ 取消即可，不必真的停用。

## 五、现场常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开 5173 空白 | 前端未启动 | `.\scripts\start_demo.ps1`（会自动跳过已在跑的后端） |
| 登录报"请求失败" | 后端未启动或端口被占 | 看后端窗口；或 `.\scripts\stop_demo.ps1` 后重启 |
| 解析总显示"规则解析" | 模型密钥错误或网络不通 | 这是**设计好的降级**，可直接讲"模型不可用时系统仍可用"；若要展示模型，检查 `backend\.env` 的 `PROVIDER_KEY` |
| 数据不是 22 个任务 | 之前演示改过 | `.\scripts\start_demo.ps1 -Reset`（注意会清空打卡记录） |
| 端口被占用 | 上次没停干净 | `.\scripts\stop_demo.ps1` |

## 六、一句话卖点（讲的时候用）

- **不是日程表**：目标 + 截止 + 可用时间进来，容量 C/B/C′ 算出来，先判断"排不排得下"，再谈怎么排。
- **程序说了算**：容量、7:3 拆分、装箱、校验都是确定性算法，有 482 项测试、覆盖率 100%。
- **模型只做它擅长的**：只有"这句话想学什么"交给大模型；规则能命中就不调模型（0.01 s vs 1 s）。
- **可追溯**：版本只读快照、事件只追加、调整必须填原因，改错了只能"更正"不能删。
